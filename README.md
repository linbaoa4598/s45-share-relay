# S45 Share Relay

原项目 S45 共享协议的网页查看器与 TCP → WebSocket 中转。不是 S44 移植版协议。
无第三方 npm 依赖，Node.js 22+；Docker 使用 Node.js 24。

## 本地运行

```sh
npm test
npm start
```

浏览器访问 http://127.0.0.1:8888；TCP 默认 9999。
默认仅监听本机。如需可信局域网使用，设置 HOST=0.0.0.0。

## Railway 部署

1. Railway 新建服务，选择此 GitHub 仓库；Dockerfile、railway.json 会配置构建与健康检查。
2. **第一次部署前**在 Variables 设置：
   - TCP_PORT：9999
   - HOST：0.0.0.0
3. Deploy 后生成 HTTP Public Domain。程序读取 Railway 的 PORT，网页自动使用同域 WSS。
4. 在 Networking 添加 **TCP Proxy**，内部目标端口填写 9999。
5. 手机原项目配置中的“共享服务器”填写 Railway 分配的 TCP 代理域名，
   “共享端口”填写分配的**外部代理端口**，不是网页域名/443，也通常不是9999。
6. 浏览器打开 HTTPS 公网域名，直接输入六位房间号，无需用户名或密码。

仅部署**一个区域、一个实例**。房间保存在进程内存，多副本无法同步；
发布更新会暂时断流，浏览器会自动重连，房间须等待手机重新上传。
不要启用 Serverless/休眠，以免长连接被挂起。
本版本已移除网页登录和密码启动检查，无需设置 WEB_USER 或 WEB_PASSWORD；旧变量存在也会被忽略，可自行删除。
/healthz 是不含对局数据的公开健康端点。
网页、在线房间列表和 WebSocket 均可公开访问；手机旧 TCP 协议也没有认证能力。

原始项目配置键：

```ini
共享服务器=<Railway TCP代理域名>
共享端口=<Railway TCP代理外部端口>
共享频率=20
共享输出宽度=2400
共享重连间隔=2000
```

不要使用 S44 移植版的 ShareLoad 配置方式。
原程序的解析器是否支持代理域名需真机验证；重建 UI 的连接入口目前只接受数字 IPv4。
不要把 DNS 解析得到的临时地址当成长期固定 IP。

文档：[TCP Proxy](https://docs.railway.com/networking/tcp-proxy)、
[Healthchecks](https://docs.railway.com/deployments/healthchecks)。

## 协议与限制

```text
gameData<六位数字房间>[==][==]<人物>---<野怪>---<兵线>
```

- 三组分别 10 / 5 / 3 列（另兼容旧重建工程的 9 列人物），逗号分列，== 结束一条记录。没有第四个阵营段。
- TCP 没有消息长度或结束符。中转以**下一帧头**划分上一帧，通常延迟一帧；
  只有一帧且连接不断开时不会猜测边界。正常 EOF 尝试提交最后完整帧。
- 人物 F9 不认定为阵营，F4/F5/F8/F9/F10 保留原始数字，不猜测 CD 单位。
- 野怪显示原始 F2/F3；兵线按实际上传绘制，不套用 S44 的固定 70 或缺兵线假设。
- 人物/野怪地图边长按“共享输出宽度 / 11.2 × 1.455”转换；
  人物中心补回原头像坐标减去的20像素。各组偏移可在网页独立校准。
- 兵线默认还原世界坐标后投影：world=(wire-offset)*2400/共享输出宽度，地图范围±50000。原程序仅发送敌方兵线，按该阵营推导本方方向；也可手动指定方向。保留旧地图像素模式。
- 网页3秒无更新清除标记，房间10秒无更新移除；断线2秒后重连。
- 当前还原工程没有把采集结果自动接入共享打包，手工共享入口与原始 ELF 是不同验证对象。
- 单元测试与回环测试不代表原始程序、手机真实对局或 Railway 云端验证成功。

## 公网风险

**本版本无网页登录验证，任何能访问网址的人均可查看在线房间和共享数据。** 旧协议无认证、无加密，第三方可能注入相同房间数据。
六位房间号不是密码；不要传输敏感数据。若需要可靠的公网上传身份认证，应先修改手机
发送端和中转协议，或使用受控隧道/网络访问限制。本项目不假装解决旧协议缺失的认证。

本仓库仅包含部署所需网页、中转、测试与配置，不包含原始 ELF、逆向资料、授权卡密、
本地备份或测试二进制。没有声明对第三方地图素材授予新的许可。

## 对局重连修复

早期版本把原始人物帧错误判断为9列，遇到实际10列会拒绝整帧并关闭TCP。
主菜单的空人物帧仍可通过，因此会出现“进对局无房间、退对局有房间”。
修复版接受原始10列并兼容旧重建9列。F8的原始%f输出保留，NaN/Inf转为展示null。
已知帧头之间的错误帧仅丢弃，不关闭上传连接，后面的正常帧仍继续处理。
无效前缀、超过缓存限制等流级错误仍会断开；不会无限缓存或吞掉资源限制。
Railway日志前缀[s45-share]，事件frame_rejected会显示组名和实际列数，
tcp_fatal为流级错误；日志有节流且不包含原始对局内容或房间号。
静态证据：原始0x1b02644依次拼接7个字段，再调用0x1d4acec追加%f字段，
随后还有两个整数和两个逗号，共10列。此前反编译在该浮点调用处漏显参数，
旧9列合成测试无法覆盖实战帧。当前回归增加10列、负坐标、非有限F8和坏帧后恢复场景。
这仍不是手机或Railway真实对局验证；更新后请检查最新提交和日志。

## 兵线收到了却看不到的修复

此前把兵线原始坐标误用人物的约312像素边长，导致数万量级的兵线点全部落在画布外。
原始0x1b02644兵线分支将世界坐标乘以共享输出宽度/2400，再加兵线偏移；
不含人物/野怪的半边长投影。新版默认还原世界坐标再投影至680画布，增加可见/画布外计数。
方向证据：原循环过滤掉本方阵营，仅上传敌方；本方1为+1，本方2为-1。
自动方向仅在兵线有效阵营唯一时使用，混合/未知阵营不猜测，提示待校准。
网页共享输出宽度应与脚本配置一致，默认2400；兵线左/上为发送端线性偏移，世界跨度默认100000。
本次读到用户房间的兵线值（例如46815,-31992）并验证其落在世界范围；
不把合成测试冒充手机对局端到端验证，也不会把越界点强行夹到地图边缘。

## 英雄头像与我方视野

敌方英雄使用本仓库heroes/目录内的133张PNG，来自原项目已提取、按资源表索引匹配的头像。
无需浏览器访问第三方网站；地图和侧栏均显示头像，加载中/缺失时回退英雄ID数字。
Dockerfile会复制该目录。头像只按实际上传的英雄ID加载。

原始0x1b02644人物循环明确要求阵营不等于本方，仅封包敌方；原协议也没有战争迷雾、
眼位或我方视野覆盖字段。因此本次网页更新没有补齐我方英雄/战争迷雾。
显示我方英雄需要修改手机端采集和共享分支；视野覆盖还需要额外定义并采集相关数据。
不使用假位置、模拟迷雾或从敌方位置猜测我方视野。
